# 액화수소 탱크 단열 설계 대리모델 (LH2 Insulation Surrogate) Constitution

## Core Principles

### I. 물리 모델이 기준이다 (Physics as Ground Truth)

- `physics/`의 간이 ODE 모델(`BoiloffModel`, `evaluate_cost`)이 모든 예측·비용 값의
  기준(reference)이다. 대리모델은 이를 빠르게 근사하는 도구일 뿐 대체하지 않는다.
- 대리모델로 얻은 최적 설계안은 MUST ODE로 재계산(재검증)한 뒤에만 결과로 보고한다.
- 대리모델 평가는 MUST 같은 입력에 대한 ODE 결과와의 오차(RMSE, R², 365일 잔량비 오차,
  최적 총비용 상대오차)로 수행한다.
- 물리 모델 변경은 MUST 데이터셋 재생성과 대리모델 재학습 필요 여부를 함께 판단·기록한다.

**근거**: 대리모델의 가치는 ODE를 충실히 근사하는 데 있으며, 기준이 흔들리면 학습·최적화
결과 전체를 신뢰할 수 없다.

### II. 물리 경향 테스트 우선 (NON-NEGOTIABLE)

- 물리·비용 모델의 모든 동작 변경은 MUST pytest 테스트(`tests/`)로 뒷받침한다.
- 테스트는 정확한 수치보다 **물리적 경향과 극한 조건**을 검증한다. 예: N ↑ → 열유입 ↓,
  진공압 ↑ → 보일오프 ↑, L/D = 0 ↔ 구형 탱크 일치, 총비용 U자형, 근사식 N*와의 일치 허용오차.
- 새 기능은 MUST 실패하는 테스트를 먼저 작성하거나, 최소한 구현과 같은 변경에 테스트를 포함한다.
- 기존 테스트가 실패한 상태로 다음 단계(데이터 생성, 학습, 최적화, UI)로 진행해서는 안 된다(MUST NOT).

**근거**: 정확도보다 경향성이 목표인 간이 모델이므로, 경향을 자동으로 지키는 테스트가 유일한
품질 보증 수단이다.

### III. 단위·가정·출처 명시

- 물리 상수와 변수는 MUST 단위를 주석 또는 이름에 `[단위]` 형식으로 표기한다
  (예: `H_FG = 446e3  # 증발잠열 [J/kg]`). 내부 계산은 SI 단위를 쓰고, 문헌 식이 다른 단위를
  쓰면(Lockheed 식의 torr, layers/cm) MUST 변환 지점을 명시한다.
- 경험식과 계수는 MUST 출처를 남긴다(예: Keller et al. 1974).
- 단순화 가정(벤트 개방·압력 일정, 열성층·ortho-para 무시 등)을 추가·변경하면 MUST
  `PLAN.md`의 해당 절을 같은 변경에서 갱신한다.

**근거**: 단위 혼동과 숨은 가정은 간이 모델에서 가장 흔하고 찾기 어려운 오류 원인이다.

### IV. 경제 변수는 후처리로 분리

- 경제 변수(c_layer, c_fixed, p_H2, 수명 Y, 할인율 r)는 MUST NOT 대리모델 입력이나 학습
  데이터에 포함한다. 비용은 MUST 잔량비 곡선과 형상에서 `cost_from_curve`로 계산한다.
- 데이터셋에는 비용 값을 저장하지 않는다(MUST NOT).
- 1년 안에 소진되는 설계(`depleted`)는 MUST 비용 최적화에서 제약 위반으로 처리한다
  (손실이 m0에서 잘려 비용이 과소평가되기 때문).
- 비용이 정의되지 않은 설계변수(현재 N̄, ε)는 비용 항이 추가되기 전까지 MUST 최적화 변수에서
  제외하고 고정한다.

**근거**: 가격 변경 시 재학습 없이 UI에서 즉시 최적점을 재계산할 수 있어야 하며, 비용 없는
변수는 최적화가 무조건 경계로 보내는 왜곡을 만든다.

### V. 학습 범위 준수와 재현성

- 대리모델 입력은 MUST 학습 데이터의 샘플링 범위(PLAN.md 3.1) 안으로 제한한다. UI와 최적화는
  범위 밖 입력을 받지 않는다(외삽 금지).
- 최적해가 학습 범위 경계에 붙으면 MUST 이를 보고하고 범위 확장·데이터 재생성 여부를 판단한다.
- 데이터 생성(LHS), 데이터 분할, 학습, 하이퍼파라미터 탐색은 MUST 난수 시드를 고정·기록하여
  같은 설정으로 같은 결과를 재현할 수 있어야 한다.
- 생성 데이터셋과 학습된 모델은 MUST 생성 설정(입력 범위, 샘플 수, 시드, 물리 모델 버전)과
  함께 저장한다.

**근거**: 대리모델은 학습 범위 밖에서 근거 없는 값을 내며, 재현할 수 없는 결과는 검증할 수 없다.

### VI. 단순성과 파이프라인 완성 우선

- 목표는 정확도가 아니라 **물리 모델링 → 데이터 생성 → 학습 → 최적화 → UI 파이프라인의 완성**이다.
- 각 단계는 MUST 가장 단순한 동작 버전을 먼저 끝까지 연결한 뒤 개선한다.
- PLAN.md 10장의 확장 아이디어(밀폐 탱크 압력, ortho-para, 불확실성 정량화 등)는 핵심 파이프라인
  완성 전에 착수하지 않는다(MUST NOT).
- 새 의존성, 추상화 계층, 추가 모델은 SHOULD 구체적인 필요(테스트 실패, 측정된 성능 부족)로
  정당화한다.

**근거**: 6주 캡스톤 일정에서 미완성 고급 기능보다 끝까지 동작하는 단순한 파이프라인이 더 가치 있다.

## 기술·보안 제약

- **언어/런타임**: Python 3. 수치 계산은 numpy/scipy(`solve_ivp`), 테스트는 pytest를 쓴다.
- **도구**: 하이퍼파라미터 탐색과 대리모델 최적화는 Optuna, 웹 UI는 Streamlit을 기본으로 한다.
  MLP 프레임워크는 학습 단계 plan에서 결정하고 그 근거를 기록한다.
- **구조**: 모듈은 PLAN.md 7장의 디렉터리(`physics/`, `data/`, `surrogate/`, `optimize/`, `app/`,
  `notebooks/`)를 따른다. `physics/`는 ML·UI 코드에 의존해서는 안 된다(MUST NOT).
- **보안**: 실제 업무 모델, 사내 데이터, 비공개 계수는 MUST NOT 저장소에 포함한다. 모든 물리
  모델과 계수는 공개 문헌 수준이어야 한다.
- **다중 사용자 UI**: 모델은 시작 시 한 번만 로드(캐싱)하고, 사용자별 상태는 세션 상태에 둔다.

## 개발 워크플로와 품질 게이트

- 기능 작업은 Spec Kit 흐름(`/speckit-specify` → `/speckit-plan` → `/speckit-tasks` →
  `/speckit-implement`)을 따르며, plan 단계의 Constitution Check에서 본 원칙 위반 여부를 점검한다.
- 단계별 완료 기준(PLAN.md 8장)을 품질 게이트로 쓴다.
  - 물리·비용 모델: PLAN.md 2.4 체크리스트 테스트 통과
  - 데이터: 분포·소진 비율·민감도 점검 완료
  - 대리모델: 테스트 R² ≥ 0.99 목표, ODE 대비 추론 속도 측정
  - 최적화: 대리모델 최적 N이 ODE 최적 N과 ±2층 이내, 최적 총비용 오차를 주 지표로 보고
  - UI: 4개 탭(예측·비교·검증·최적화) 동작
- 모든 변경은 MUST `pytest`가 전부 통과하는 상태로 마무리한다.
- 원칙 위반이 불가피하면 MUST plan의 Complexity Tracking에 이유와 기각한 단순 대안을 기록한다.

## Governance

- 본 헌법은 프로젝트의 다른 관행과 문서보다 우선한다. `PLAN.md`는 설계 세부와 런타임 개발
  지침을 담으며, 헌법과 충돌하면 헌법을 따르고 `PLAN.md`를 수정한다.
- **개정 절차**: `/speckit-constitution`으로 개정안을 작성하고, Sync Impact Report로 변경 내용을
  검토한 뒤 반영한다. 개정은 이유와 영향받는 산출물(spec, plan, tasks, 테스트)을 함께 기록한다.
- **버전 정책**: 시맨틱 버저닝을 따른다. MAJOR는 원칙 삭제·재정의 등 하위 호환이 깨지는 변경,
  MINOR는 원칙·섹션 추가 또는 지침의 실질적 확장, PATCH는 문구 명확화·오탈자 수정이다.
- **준수 점검**: 모든 plan은 Constitution Check를 통과해야 하며, 구현 리뷰와 `/speckit-analyze`는
  본 원칙 준수 여부를 확인한다. 정당화되지 않은 복잡성은 거부한다.
