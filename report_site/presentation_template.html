01 · 문제

단열 사양이 바뀔 때마다 계산을 처음부터 다시 한다

반복되는 일

적층수·진공압·탱크 크기를 바꿀 때마다 1년 보일오프 ODE를 다시 풀고, 비용표를 손으로 다시 만든다.

바뀌는 조건

수소 가격, 층당 시공비, 수명, 할인율. 조건이 바뀌면 최적 적층수도 바뀐다.

알고 싶은 것

MLI를 몇 겹 감아야 (적층 비용 + 보일오프 손실)이 가장 싼가. 그 답을 믿어도 되는가.

목표: 설계 변수 10개 → 0~365일 잔량 곡선을 즉시 예측하는 대리모델을 만들고, 그 모델로 비용 최적화를 한다. 기준은 언제나 물리 모델(ODE)이고, 대리모델 결과는 ODE로 다시 확인한다.
공개 문헌 수준의 간이 물리 모델(Lockheed MLI 식, 캡슐 탱크) · 실제 사내 데이터 없음

05 · deny와 훅

생성물은 스크립트로만, 물리 모델은 확인 후에만

권한 규칙 .claude/settings.json

denyEdit(/reports/**)지표 JSON·보고서 손으로 수정 금지
denyEdit(/models/**)학습 결과물은 학습 스크립트로만
denyEdit(/data/datasets/**)데이터셋은 data.generate로만
denyrm -rf · Remove-Item -Recurse일괄 삭제 방지
askEdit(/physics/**)바뀌면 데이터·모델 전부 무효

백업 훅 guard_protected.py (PreToolUse)

  • 규칙은 경로 표기(대소문자, \·/, ..)에 따라 빠질 수 있다 → 실제 경로를 계산해 다시 판정
  • 셸 명령이 physics/에 쓰는지 감지: 리다이렉트, Set-Content, cp/mv 대상, python open(...,'w')
  • 재귀 삭제 변형까지 차단: rm -fr, -R, rmdir /s, shutil.rmtree
  • 입력을 못 읽으면 통과가 아니라 차단(fail-closed)
  • 못 잡는 것도 명시: 스크립트 파일 안·변수로 만든 경로
실제로 동작했다: 샌드박스가 스크립트의 models/·data/datasets/ 쓰기까지 막아, 생성물은 명시적으로 승인한 스크립트 실행으로만 만들어졌다. 훅은 입력 JSON을 넣어 판정을 시험(models 쓰기 → deny, physics 수정 → ask, app 수정 → 통과).
테스트·시험 생성은 생성물 폴더가 아니라 tmp_path로 출력 · 메모리 안 변이 확인은 막지 않음
06 · 에이전트

만드는 에이전트와 의심하는 에이전트를 나눴다

builder 구현 담당

도구 Read · Grep · Glob · Edit · Write · Bash · PowerShell

  • tasks.md의 지정 작업만 (한 번에 한 Phase)
  • 테스트를 먼저 쓰고 실패를 확인한 뒤 구현
  • "완료" 대신 재현 명령·바뀐 파일·남긴 이슈로 보고
  • 훅·권한에 막히면 우회하지 않고 보고

verifier 검증 담당 (읽기 전용)

도구 Read · Grep · Glob · Bash · PowerShell — Edit·Write 없음

  • 맞다는 증거가 아니라 반례를 찾는다
  • 작업 ID·파일·명령만 받는다 — builder의 결론은 받지 않음
  • 변이 확인: 함수를 메모리에서 틀리게 바꿔 테스트가 잡는지

반려 규칙

작업마다 2회까지. 두 번 반려되면 builder에게 다시 보내지 않고 사람이 결정.

완료 표시

tasks.md의 [X]는 verifier가 반례를 못 찾고, 메인 세션이 직접 재현한 작업에만.

운영

서브에이전트는 sonnet. 같은 파일을 두 builder가 동시에 고치지 않게 작업을 나눔.

.claude/agents/builder.md · verifier.md (lh2-kit 플러그인에 포함)
