# Phase 0 Research: 대리모델 학습용 데이터셋 생성

Technical Context에 남은 미결 사항과 기술 선택을 정리한다. 각 항목은 결정 / 근거 / 검토한 대안 순서로 쓴다.

## R1. 데이터셋 저장 형식

- **Decision**: 숫자 배열은 NumPy `.npz`(비압축) 파일 하나에 담고, 생성 설정·요약은 JSON, 제외 기록은 CSV로
  같은 디렉터리에 둔다.
- **Rationale**: 데이터는 1만 × (입력 10 + 곡선 100 + 보조 5)개, 약 9 MB로 작다. `.npz`는 numpy만 있으면
  읽을 수 있고 float64를 그대로 보존하므로 SC-003(재계산 차이 1e-6 이하)을 만족한다. 002 학습 코드가
  추가 가공 없이 `X`, `Y`를 바로 불러올 수 있다(FR-015). JSON·CSV는 사람이 바로 열어 볼 수 있다.
- **Alternatives considered**:
  - Parquet(pyarrow 설치돼 있음): 표 형태에는 좋지만 곡선 100개를 열 100개로 펼치거나 리스트 열로 넣어야
    한다. 이 규모에서는 장점이 없고 의존성만 는다.
  - HDF5: 계층 구조가 필요할 만큼 데이터가 복잡하지 않다. 의존성(h5py)이 추가된다.
  - CSV 한 파일: float 정밀도 손실과 파일 크기 문제가 있다.

## R2. Latin Hypercube 샘플링과 시드 관리

- **Decision**: `scipy.stats.qmc.LatinHypercube(d=10, rng=<Generator>)`로 [0,1)^10 단위 샘플을 뽑은 뒤
  변수별로 변환한다. 마스터 시드 하나에서 `numpy.random.SeedSequence(seed).spawn(3)`으로 LHS·분할·부분
  데이터셋용 시드를 따로 만든다.
- **Rationale**: scipy는 이미 의존성이고(1.17.1), qmc의 LHS는 층화가 보장된다. 용도별로 시드를 분리해 두면
  부분 데이터셋 기능을 바꿔도 LHS 결과가 달라지지 않는다(FR-013). scipy 1.15부터 qmc는 `seed` 대신
  `rng` 키워드를 쓴다.
- **Alternatives considered**: 직접 구현한 LHS는 검증 부담이 생긴다. Sobol 수열은 샘플 수가 2의 거듭제곱일
  때 가장 좋아서 1만 개 기본값과 맞지 않고, PLAN.md가 LHS로 정해 두었다.

## R3. 변수 변환 (선형, 로그, 정수)

- **Decision**:
  - 선형 변수: `x = lo + u·(hi − lo)`
  - 로그 변수(G_sup, P_v0, G, S): `x = 10^(log10 lo + u·(log10 hi − log10 lo))`
  - 정수 변수(N): `x = lo + floor(u·(hi − lo + 1))`를 [lo, hi]로 자른다. 10~120의 정수 111개가 거의 같은
    확률로 나오고, 양 끝(10, 120)도 다른 값과 같은 확률로 뽑힌다.
- **Rationale**: 실수를 뽑아 반올림(`round`)하면 양 끝 정수가 나올 확률이 절반으로 줄어든다(Edge Case).
  floor 방식은 각 정수 구간의 폭이 같다.
- **Alternatives considered**: `round(lo + u·(hi−lo))`는 끝값 확률이 1/2이다. `[lo−0.5, hi+0.5)`에서 뽑아
  반올림하는 방식은 floor와 같은 결과지만 덜 직관적이다.

## R4. 소진 시점을 정확히 얻는 방법

- **Decision**: `physics.model.BoiloffModel`에 소진 이벤트 시각을 함께 돌려주는 메서드
  `simulate_detailed(days, n_points)`를 **추가**한다. 반환값은 `(t [day], ratio, t_empty [day] 또는 inf)`이다.
  기존 `simulate()`는 이 메서드를 호출해 앞의 두 값만 돌려주도록 바꿔 동작을 그대로 유지한다.
- **Rationale**: 지금 `simulate()`는 ODE의 소진 이벤트 시각(`sol.t_events`)을 버린다. `evaluate_cost`는 격자에서
  처음 0이 되는 시점으로 근사하므로 오차가 최대 약 3.7일이다. 데이터 생성 모듈에서 `solve_ivp`를 다시
  호출하면 ODE 풀이 코드가 두 벌이 되어 헌법 원칙 I(물리 모델이 유일한 기준)에 어긋난다.
- **헌법 원칙 I 영향 판단**: 기능만 추가하고 기존 출력은 바꾸지 않는다. 기존 테스트 44개가 그대로 통과해야
  하고, `t_empty`가 격자 근사값과 3.7일 이내로 맞는지 확인하는 테스트를 하나 추가한다. 물리 모델 해시는
  달라지지만 아직 생성된 데이터셋이 없으므로 재생성할 대상이 없다.
- **Alternatives considered**: 격자 근사값을 그대로 쓰면 소진 시점 학습용 보조 출력이 부정확해진다.
  데이터 모듈에서 ODE를 직접 풀면 코드가 중복된다.

## R5. 물리 모델 버전 식별 (Clarification 2)

- **Decision**:
  - `physics/__init__.py`에 `PHYSICS_VERSION = "0.1.0"`을 추가한다(사람이 관리).
  - 해시는 `physics/*.py` 파일을 이름순으로 정렬해 내용을 읽고, 줄바꿈을 `\n`으로 통일한 뒤 SHA-256으로
    계산한다. 파일 이름도 해시에 포함한다. `__pycache__`는 제외한다.
  - `data.versioning.physics_fingerprint()`가 `{"version": ..., "sha256": ...}`을 돌려준다.
- **Rationale**: 줄바꿈을 통일해야 Windows(CRLF)와 다른 환경 사이에서 해시가 흔들리지 않는다. 파일 이름을
  넣어야 파일 추가·삭제도 잡아낸다. git이 없으므로 내용 기반 해시가 가장 확실하다.
- **Alternatives considered**: 파일 수정 시각은 내용이 같아도 바뀐다. 모듈 바이트코드 해시는 Python
  버전마다 다르다.

## R6. 품질 필터 기준 (FR-010)

- **Decision**: 아래 중 하나라도 해당하면 제외하고 사유 코드를 기록한다.
  | 사유 코드 | 조건 |
  |---|---|
  | `solver_error` | 시뮬레이션이 예외를 던짐 |
  | `nan` | 곡선 또는 보조 출력에 NaN 또는 ±inf(소진 시점의 inf는 정상으로 봄) |
  | `negative` | 잔량비 < 0 |
  | `above_one` | 잔량비 > 1 + 1e-9 |
  | `increasing` | 인접 시점 차이 > 1e-9 (잔량이 늘어남) |
  | `initial_not_one` | 첫 시점 잔량비가 1에서 1e-12보다 크게 벗어남. 1e-12 이내면 정확히 1.0으로 맞춘다(ODE 풀이기가 t=0에서 1 − 2e-16을 돌려주는 경우가 약 13%, 검증 1회차 발견 #3) |
- **Rationale**: 현재 물리 모델은 잔량비를 [0,1]로 자르므로 `negative`·`above_one`은 나오지 않아야 한다. 그래도
  모델이 바뀔 때를 대비해 방어 검사로 남긴다. 1e-9는 ODE 허용오차(rtol 1e-8)보다 작아 실제 증가만 잡는다.

## R7. 분할과 부분 데이터셋 (Clarification 4)

- **Decision**:
  - 분할: 유효 샘플을 분할 시드로 섞은 뒤 `n_train = round(0.70·n)`, `n_val = round(0.15·n)`,
    `n_test = n − n_train − n_val`로 나눈다.
  - 부분 데이터셋: 부분 데이터셋 시드(정수, `SeedSequence(seed).spawn(3)[2].generate_state(1)[0]`)로 유효 샘플
    전체를 한 번 섞어 순서를 정하고, 크기 k의 부분 데이터셋은 그 순서의 앞 k개로 한다. 따라서 작은 부분
    데이터셋은 항상 큰 부분 데이터셋에 포함된다. 부분 데이터셋마다 같은 분할 규칙을 따로 적용하며, 크기 k의
    분할 시드는 `SeedSequence([subset_seed, k])`로 만든다. 분할이 k만으로 정해지므로 다른 크기를 함께
    요청하든 따로 요청하든 결과가 같다.
  - 요청 크기 k가 유효 샘플 수보다 크면 오류를 낸다.
- **Rationale**: `round` 기반 크기 계산은 SC-006(비율 ±1개)을 만족한다. 순서를 한 번만 정하면 중첩이 자동으로
  보장된다.
- **Alternatives considered**: 층화 분할은 Assumptions에 따라 SC-006을 못 맞출 때만 쓴다. 사전 시뮬레이션
  기준 소진 비율 20%에서 1만 개를 무작위로 나누면 세트별 소진 비율의 표준편차는 약 1%p라 5%p 기준에 여유가
  크다. 1k 부분 데이터셋의 검증·테스트(150개)에서는 표준편차가 약 3.3%p라 기준을 넘을 수 있으므로, SC-006은
  전체 데이터셋에만 적용한다.

## R8. 점검 보고서

- **Decision**: matplotlib(Agg 백엔드)로 PNG 그림 4개를 만들고, 요약 수치와 경고를 `inspection.json`과
  사람이 읽는 `report.md`에 함께 쓴다.
  - `curves.png`: 무작위 곡선 50개를 겹쳐 그리고, 소진 샘플은 다른 색으로 표시
  - `ratio365_hist.png`: 365일 잔량비 히스토그램(구간 폭 0.05)
  - `sensitivity.png`: 입력별 Spearman 순위상관(막대)
  - `scatter.png`: 입력 10개 대 365일 잔량비 산점도(2×5, 로그 변수는 로그 축)
- **Rationale**: Spec Deferred 항목이던 "산점도 대 상관계수"는 둘 다 만든다. 비용이 거의 없고, 상관계수는
  한눈에 순위를 보여 주고 산점도는 비선형성을 보여 준다. Spearman은 단조 비선형 관계도 잡는다. 노트북 없이
  명령줄만으로 결과가 남아 SC-007(5분 안에 판단)에 맞는다.
- **경고 규칙**: 소진 비율 > 30%, 365일 잔량비가 [0, 0.1] 또는 [0.9, 1.0] 한쪽에 50% 이상, 제외 비율 > 1%,
  세트별 소진 비율 차이 > 5%p.
- **의존성**: matplotlib이 현재 환경에 없으므로 `requirements.txt`에 추가한다.

## R10. 원자적 저장과 덮어쓰기 보호 (FR-016, FR-017)

- **Decision**: `<out>/<name>.partial/`에 모든 파일을 쓴 뒤, 마지막에 `os.replace`로 `<out>/<name>/`으로 이름을
  바꾼다. 실패하거나 중단(KeyboardInterrupt 포함)되면 `.partial` 디렉터리를 지운다. 대상 디렉터리가 이미
  있으면 `--overwrite`가 없을 때 시작 전에 오류로 멈춘다. `--overwrite`이면 새 데이터셋이 완성된 뒤에만
  기존 것을 지운다.
- **Rationale**: 같은 파일 시스템 안의 디렉터리 이름 변경은 원자적이라, 완성되지 않은 데이터셋이 정상 경로에
  남지 않는다.
- **기본 이름**: `lhs_n{요청수}_seed{시드}`. 같은 설정을 다시 실행하면 같은 이름이 되므로 덮어쓰기 보호가
  작동한다.
