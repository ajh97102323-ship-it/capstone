# Phase 0 Research: 잔량 곡선 대리모델 학습과 평가

결정마다 Decision / Rationale / Alternatives considered 순서로 쓴다. 근거가 된 사전 실험(R0)은 001 기본 데이터셋
`data/datasets/lhs_n10000_seed42`(학습 7000 / 검증 1500 / 테스트 1500)로 2026-11-13에 수행했다.

## R0. 사전 실험 결과 (scikit-learn MLP, 은닉 3층, Adam, 조기 종료, 후처리 포함)

| 입력 특성 | 은닉층 | 학습 시간 | 테스트 R² | 365일 평균 오차 | 365일 최대 오차 | 1000개 추론 |
|---|---|---|---|---|---|---|
| 설계 입력 10개 | 128×3 | 15 s | 0.99871 | 0.0078 | 0.054 | 1.8 ms |
| 설계 입력 10개 | 256×3 | 31 s | 0.99880 | 0.0060 | 0.067 | 3.7 ms |
| + 정확한 k (BoiloffModel로 계산) | 128×3 | 14 s | 0.99947 | **0.0046** | 0.042 | 약 50 ms (ODE의 약 41배 속도) |
| + 근사 k_tot (전 면적 기준, 배열 계산) | 128×3 | – | 0.99911 | 0.0058 | 0.066 | 2.7 ms (ODE의 약 890배) |

- ODE는 샘플당 약 2.0~2.4 ms(1000개 약 2.4 s)다.
- **SC-001(R² ≥ 0.99)은 모든 설정에서 충족했다.** SC-002 평균(≤ 0.005)은 정확한 k를 넣어야 충족했다. SC-002 최대(≤ 0.03)는 아직 어떤 설정도 충족하지 못했다(R8).
- 후처리(R3)로 SC-004(0~1, 단조 비증가)는 구조적으로 보장된다.

## R1. 학습 프레임워크

- **Decision**: scikit-learn `MLPRegressor`를 쓴다. 학습 루프는 `partial_fit`으로 한 epoch씩 직접 돌려 001의 검증 세트로 조기 종료하고, 가장 좋았던 가중치를 저장한다(R4).
- **Rationale**: 이미 설치돼 있고(Python 3.13 지원), R0에서 R² 0.999를 15~30초 학습으로 얻었다. 출력층 커스텀이나 사용자 정의 손실 없이도 후처리로 FR-006을 보장할 수 있다. 의존성과 코드가 가장 적다(헌법 원칙 VI). 헌법 기술 제약("MLP 프레임워크는 학습 단계 plan에서 결정하고 근거를 기록")에 따라 여기에 기록한다.
- **Alternatives considered**:
  - PyTorch: 단조 출력층(감소분 softplus 누적합)과 가중 손실을 자유롭게 쓸 수 있지만, 설치되어 있지 않고(약 200 MB) 코드가 늘어난다. SC-002 최대 오차를 튜닝·앙상블로도 못 맞추면 그때 검토한다.
  - 주성분 + 회귀(FR-012, 선택): 비교 모델로만 남긴다(User Story 4, P3).

## R2. 입력 특성: 설계 입력 10개 + 물리 특성 k

- **Decision**: 입력은 (a) 설계 입력 10개(로그 스케일 4개는 log10 변환)와 (b) 물리 특성 `log10(k)` 하나, 모두 11개다. k는 초기 일일 증발 비율 [1/day]이다.
  ```
  k = [ q·A_tot·(w + η·(1 − w)) + G_sup·(T_h − T_c) ] / (h_fg · ρ_l · V_tot · fill) × 86400
  q = mli_heat_flux(N, N̄, ε, P_v0, T_h, T_c)              (physics.heat, 배열 계산 가능)
  w = A_wet(h0)/A_tot  : 초기 젖음 면적 비율, fill과 L/D만의 함수 (R에 무관)
  ```
  w는 모듈을 불러올 때 `physics.geometry.CapsuleTank(R=1, L=2·L/D)`로 (fill, L/D) 격자(예: 91 × 61)에서 한 번만 계산한 표를 2차원 보간해 얻는다.
- **Rationale**:
  - k는 ODE 없이 계산되며 곡선 기울기를 거의 결정하므로, R0에서 365일 평균 오차를 0.0060 → 0.0046으로 낮췄다.
  - 샘플마다 `BoiloffModel`을 만들면 추론이 ODE의 약 41배 속도에 그쳐 SC-003(100배)을 못 맞춘다. w 표를 쓰면 모든 계산이 배열 연산이 되어 근사 k_tot(약 890배)와 비슷한 속도가 나온다.
  - w와 k의 식은 `physics/`의 함수와 상수(`mli_heat_flux`, `CapsuleTank`, `H_FG`, `T_C`, `RHO_L`, `ETA`)를 그대로 써서 만든다. ODE를 복제하지 않는다(헌법 원칙 I). k가 `BoiloffModel.heat_to_liquid(0, m0)`로 계산한 값과 상대 1e-3 이내로 같은지 테스트로 고정한다.
  - 경제 변수는 쓰지 않는다(헌법 원칙 IV).
- **Alternatives considered**: 설계 입력만 쓰기(평균 오차 0.0060으로 SC-002 미달), 근사 k_tot(0.0058로 미달), 샘플마다 BoiloffModel 생성(SC-003 미달).

## R3. 출력과 후처리

- **Decision**: 모델은 시점 1~99의 잔량비 99개를 출력한다(시점 0은 항상 1). 예측 뒤 `[0, 1]`로 자르고, 맨 앞에 1을 붙이고, 누적 최솟값(`np.minimum.accumulate`)을 취한다.
- **Rationale**: FR-006(0~1, 단조 비증가)과 SC-004(위반 0건)가 구조적으로 보장된다. R0에서 이 후처리를 넣은 상태로 R² 0.999를 얻었다. 소진 이후 0 구간도 자르기로 정확히 0이 된다.
- **Alternatives considered**: sigmoid 출력층·감소분 누적합 출력층(sklearn에서 불가, PyTorch 필요), 후처리 없이 손실로만 유도(보장 불가).

## R4. 학습 절차와 조기 종료

- **Decision**: `MLPRegressor(warm_start=False)`를 만들고 `partial_fit`을 epoch 단위로 호출한다(매 epoch 학습 세트를 시드 고정으로 섞어 mini-batch). epoch마다 검증 세트 MSE(후처리 후, 곡선 99개 기준)를 재고, 최솟값이 `patience`(기본 20) epoch 동안 갱신되지 않으면 멈춘다. 가장 좋았던 epoch의 가중치(`coefs_`, `intercepts_` 깊은 복사)를 최종 모델로 쓴다. 최대 epoch 기본 400.
- **Rationale**: FR-003은 001의 검증 세트로 조기 종료와 모델 선택을 하라고 한다. sklearn 내장 `early_stopping`은 학습 세트 일부를 따로 떼어 쓰므로 FR-003·FR-004와 맞지 않는다.
- **입력 표준화**: 학습 세트의 특성 11개로 `StandardScaler`를 맞추고 모델과 함께 저장한다(FR-002).
- **시드**: 학습 시드(기본 0)로 sklearn `random_state`와 섞기 순서를 정한다. BLAS 병렬 연산 때문에 마지막 자리 차이가 날 수 있으므로 재현성은 "테스트 지표 상대 1e-6 이내"로 확인한다(spec US1 시나리오 4의 허용오차).

## R5. 학습 범위 검사

- **Decision**: 모델에 데이터셋의 `input_names`, `input_lo`, `input_hi`를 저장한다. 예측 전에 입력이 범위 안인지 확인하고, 벗어나면 `OutOfRangeError`에 벗어난 변수 이름·값·범위를 담아 던진다(FR-007, 헌법 원칙 V). 정수 변수 N은 [10, 120] 안의 실수도 받는다(최적화에서 연속 탐색할 수 있게).
- **Rationale**: 외삽 금지. 004 UI와 003 최적화가 같은 검사를 재사용한다.

## R6. 모델 저장 형식

- **Decision**: `models/<name>/`에 `model.joblib`(scaler + MLP + w 표 설정), `meta.json`(학습 설정, 시드, 학습 범위, 특성 정의, 데이터셋 경로와 물리 모델 지문, sklearn·numpy 버전, 평가 지표), `report/`(평가 보고서)를 둔다. 001과 같은 방식으로 `<name>.partial/`에 쓰고 완성되면 이름을 바꾼다.
- **Rationale**: joblib은 sklearn 모델 저장의 표준이다. 버전을 기록해 다른 환경에서 불러올 때 경고할 수 있다. 데이터셋의 물리 모델 지문을 기록해, 물리 모델이 바뀐 뒤 옛 모델을 쓰면 경고한다(001 FR-014a, 헌법 원칙 I).
- **보안 메모**: joblib(pickle)은 신뢰할 수 있는 로컬 파일만 불러온다. 이 프로젝트의 모델 파일은 직접 만든 것뿐이다.
- **Alternatives considered**: ONNX(변환 도구 추가 필요), 가중치를 npz로 직접 저장(재구성 코드가 늘어남).

## R7. 하이퍼파라미터 탐색 (User Story 2)

- **Decision**: Optuna(TPE, 시드 고정)로 은닉층 수(3~4), 노드 수(64~256), 학습률(1e-4~3e-3, log), 배치 크기(64·128·256), 가중치 감쇠 `alpha`(1e-6~1e-2, log)를 탐색한다. 목적함수는 검증 세트 MSE다. 탐색 이력은 `models/<name>/tuning.json`에 저장한다. 테스트 세트는 최종 평가에만 쓴다(FR-004).
- **의존성**: `optuna`를 `requirements.txt`에 추가한다(헌법 기술 제약의 기본 도구).

## R8. 위험: SC-002 최대 오차(≤ 0.03)

- R0의 최대 오차는 0.042~0.067이다. 오차가 큰 샘플은 소진 시점 근처 꺾임과 작은 탱크에 몰릴 것으로 예상한다(User Story 3 오차 분석으로 확인).
- **대응 순서**: (1) 하이퍼파라미터 탐색(R7) → (2) 시드가 다른 모델 5개의 평균(앙상블, 후처리 전 평균) → (3) 오차 큰 영역에 데이터 추가(001로 돌아가 적응적 샘플링) → (4) PyTorch 단조 출력층(R1 대안).
- 이 순서를 거쳐도 못 맞추면 SC-002 최대 기준을 바꿀지 사용자에게 결정을 받는다. 그때는 오차 분석 보고서와 보일오프 비용 환산 오차를 근거로 제시한다.

## R9. 평가 보고서

- **Decision**: matplotlib(Agg)로 그림을 만들고 `report.md`, `metrics.json`에 정리한다.
  - 지표: 테스트 R²(곡선 전체), RMSE, 365일 평균·최대 오차, 소진 시점 ±10일 구간 오차, 1000개 배치 추론의 ODE 대비 속도 배수, SC-001~004 통과 여부(맨 위 표시, SC-006)
  - 그림: 학습·검증 손실 이력, 오차 상위 12개 샘플의 예측 대 정답 곡선, 입력별 365일 오차 산점도, 탱크 크기(m0)별 보일오프 비용 환산 오차 분포(`p_H2·m0·|δ|`, 기본 p_H2 = 5 $/kg)
- **속도 측정**: 테스트 세트 앞 1000개를 대리모델로 배치 예측한 시간과, 같은 입력 200개를 `physics.simulate`로 푼 시간을 5배 한 값을 비교한다(1000개 전부 풀면 2초 이상 걸려 테스트가 느려지므로).
