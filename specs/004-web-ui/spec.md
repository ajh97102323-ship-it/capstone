# Feature Specification: 단열 설계 예측·최적화 웹 UI

**Feature Branch**: `004-web-ui`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "PLAN.md 6장 웹 UI 단계의 요구사항과 수용 기준"

## User Scenarios & Testing *(mandatory)*

사용자는 단열 설계를 검토하는 엔지니어(발표 청중, 팀원 포함)다. 웹 브라우저에서 설계 입력을 바꾸면
잔량 곡선과 비용을 즉시 보고, 설계안을 비교하고, AI 예측을 ODE와 대조하고, 경제 조건에 따른 최적
적층수를 찾는다. 여러 명이 동시에 접속한다.

### User Story 1 - 예측 탭: 설계 입력 → 잔량 곡선과 비용 (Priority: P1)

사용자가 설계 입력 10개를 슬라이더로 조정하면 365일 잔량 곡선과 주요 수치(초기 열유입, 지정 기간 후
잔량, 일일 보일오프율, 소진 시점, 연간 MLI 비용·보일오프 비용·총비용)가 즉시 갱신된다.

**Why this priority**: 대리모델의 존재 이유(즉시 예측)를 가장 직접적으로 보여 주는 화면이며, 이것만
있어도 데모가 가능하다.

**Independent Test**: 브라우저에서 접속해 적층수 슬라이더를 움직이며 곡선과 수치가 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 첫 접속, **When** 예측 탭을 열면, **Then** 기본 설계 입력값으로 계산된 곡선과 주요 수치가 표시된다.
2. **Given** 예측 탭, **When** 적층수를 늘리면, **Then** 1초 안에 곡선이 갱신되고 보일오프 비용은 줄고
   MLI 비용은 는다.
3. **Given** 슬라이더, **When** 범위 끝까지 움직이면, **Then** 학습 범위(PLAN.md 3.1) 밖으로는 갈 수 없다.
4. **Given** 1년 안에 소진되는 설계, **When** 결과를 보면, **Then** 소진 시점이 표시되고 비용이
   과소평가됐다는 경고가 나온다.
5. **Given** 지정 기간 입력(예: 180일), **When** 값을 바꾸면, **Then** 해당 기간 후 잔량 수치가 갱신된다.

---

### User Story 2 - 최적화 탭: 경제 조건 → 최적 적층수 (Priority: P1)

사용자가 경제 변수(층당 단가, 고정비, 수소 가격, 수명, 할인율)와 제약을 입력하면 비용 분해 U자 곡선,
최적 N, 최적 설계안의 잔량 곡선이 나온다. 가격 슬라이더를 움직이면 최적점이 실시간으로 이동한다.

**Why this priority**: 프로젝트의 핵심 결과(적층 비용 ↔ 보일오프 트레이드오프)를 보여 준다.

**Independent Test**: 수소 가격 슬라이더를 올리며 최적 N 표시가 오른쪽으로 이동하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기본 경제 조건, **When** 최적화 탭을 열면, **Then** MLI·보일오프·총비용 곡선과 최적 N,
   평평한 구간(+1%)이 표시된다.
2. **Given** 최적화 탭, **When** 수소 가격을 올리면, **Then** 1초 안에 최적 N 표시가 증가 방향으로 이동한다.
3. **Given** 최적 결과, **When** "ODE로 검증"을 요청하면, **Then** 최적 후보를 ODE로 재계산한 총비용과
   대리모델 총비용의 차이가 표시된다.
4. **Given** 최적 N이 범위 끝에 걸린 경우, **When** 결과를 보면, **Then** 경계 경고가 표시된다.

---

### User Story 3 - 검증 탭: AI 예측 vs ODE (Priority: P2)

사용자가 현재 설계로 검증을 요청하면 같은 입력에 대한 AI 예측 곡선과 ODE 곡선을 겹쳐 보고 오차를 확인한다.

**Why this priority**: 대리모델을 믿어도 되는지 사용자가 직접 확인할 수 있어야 한다(헌법 원칙 I).

**Independent Test**: 임의 설계로 검증을 실행해 두 곡선과 오차 수치가 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 현재 설계 입력, **When** 검증을 요청하면, **Then** AI·ODE 곡선이 겹쳐 그려지고 최대 오차,
   365일 잔량비 오차, 그에 따른 보일오프 비용 차이가 표시된다.
2. **Given** 검증 결과, **When** 계산 시간을 보면, **Then** AI 예측과 ODE 각각의 계산 시간이 표시된다.

---

### User Story 4 - 비교 탭: 설계안 저장과 겹쳐 보기 (Priority: P3)

사용자는 예측 탭의 현재 설계를 이름을 붙여 저장하고, 비교 탭에서 저장한 설계안 여러 개의 곡선과 비용을 겹쳐 본다.

**Why this priority**: 설계 논의에 유용하지만 다른 탭 없이는 의미가 없다.

**Independent Test**: 설계안 2개를 저장해 비교 탭에 곡선 2개와 비용 표가 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 예측 탭의 설계, **When** 이름을 붙여 저장하면, **Then** 비교 탭 목록에 나타난다.
2. **Given** 저장된 설계안 여러 개, **When** 비교 탭을 열면, **Then** 곡선이 겹쳐 그려지고 주요 수치·비용
   비교 표가 표시된다.
3. **Given** 사용자 A와 B가 동시에 접속, **When** A가 설계안을 저장하면, **Then** B의 비교 목록에는 나타나지 않는다.
4. **Given** 저장된 설계안, **When** 삭제하면, **Then** 목록과 그래프에서 사라진다.

---

### Edge Cases

- 대리모델 파일을 찾을 수 없거나 불러오지 못하면 앱은 원인 메시지를 보여 주고, 예측 대신 ODE만 쓰는
  모드로 떨어지지 않고 명확히 실패한다(조용히 다른 값을 보여 주지 않음).
- 여러 사용자가 동시에 ODE 검증을 요청해도 다른 사용자의 예측 반응이 눈에 띄게 느려지지 않아야 한다.
- 경제 변수에 0이나 음수(수명 0 등)를 넣을 수 없다. 할인율 0은 허용한다.
- 체적 고정 최적화에서 반경이 학습 범위를 벗어나는 조합은 실행 불가로 표시한다.
- 새로고침하면 세션의 저장 설계안이 사라질 수 있으며, 이를 화면에 안내한다.

## Requirements *(mandatory)*

### Functional Requirements

**공통**

- **FR-001**: 웹 브라우저로 접속하는 4개 탭(예측, 비교, 검증, 최적화)을 제공해야 한다(MUST).
- **FR-002**: 모든 설계 입력 컨트롤은 학습 범위로 제한하며, 로그 스케일 입력은 로그 눈금으로 조정할
  수 있어야 한다(MUST, 헌법 원칙 V).
- **FR-003**: 모든 수치에 단위를 표시해야 한다(MUST, 헌법 원칙 III).
- **FR-004**: 대리모델은 서버 시작 시 한 번만 불러와 모든 사용자가 공유해야 한다(MUST).
- **FR-005**: 사용자별 상태(입력값, 저장 설계안)는 사용자 세션별로 분리해야 한다(MUST).

**예측 탭**

- **FR-006**: 입력 10개로 잔량 곡선과 주요 수치(초기 열유입 [W], 지정 기간 후 잔량비, 일일 보일오프율
  [%/day], 소진 시점 [day], 연간 MLI 비용·보일오프 비용·총비용 [$/yr])를 표시해야 한다(MUST).
- **FR-007**: 소진 설계에는 소진 시점과 비용 과소평가 경고를 표시해야 한다(MUST).

**비교 탭**

- **FR-008**: 현재 설계를 이름과 함께 저장·삭제하고, 저장한 설계안의 곡선과 수치를 겹쳐 비교할 수 있어야 한다(MUST).

**검증 탭**

- **FR-009**: 현재 설계에 대해 AI 예측과 ODE 결과를 겹쳐 그리고 오차(최대 오차, 365일 잔량비 오차,
  보일오프 비용 차이)와 계산 시간을 표시해야 한다(MUST).

**최적화 탭**

- **FR-010**: 경제 변수 5개(기본값은 003과 동일)와 제약(잔량 목표, 체적·최대 직경 선택)을 입력받아야 한다(MUST).
- **FR-011**: 비용 분해 U자 곡선, 최적 N, 평평한 구간, 최적 설계안의 잔량 곡선을 표시하고, 경제 변수를
  바꾸면 자동으로 다시 계산해야 한다(MUST).
- **FR-012**: 사용자가 요청하면 최적 후보를 ODE로 재검증해 결과를 표시해야 한다(MUST).
- **FR-013**: 최적 N 경계 경고와 소진 후보 제외를 표시해야 한다(MUST).

**배포**

- **FR-014**: 서버 한 대에서 실행해 같은 네트워크의 여러 사용자가 접속할 수 있어야 하며, 실행 방법이
  문서화돼야 한다(MUST). 컨테이너 배포는 선택이다(MAY).

### Key Entities

- **사용자 세션 (Session)**: 현재 입력값, 저장 설계안 목록, 지정 기간. 사용자마다 독립.
- **저장 설계안 (Saved Design)**: 이름, 설계 입력 10개, 예측 곡선, 주요 수치.
- **경제 조건 (Economic Inputs)**: 층당 단가, 고정비, 수소 가격, 수명, 할인율, 제약.
- **공유 모델 (Shared Surrogate)**: 서버 시작 시 한 번 불러온 학습된 대리모델과 학습 범위.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 예측 탭에서 입력을 바꾼 뒤 곡선과 수치가 1초 안에 갱신된다.
- **SC-002**: 최적화 탭에서 경제 변수를 바꾼 뒤 최적 N이 1초 안에 갱신된다.
- **SC-003**: 5명이 동시에 접속해 조작해도 SC-001·SC-002를 유지한다.
- **SC-004**: 처음 쓰는 사용자가 설명 없이 3분 안에 "수소 가격 10 $/kg일 때 최적 적층수"를 찾을 수 있다.
- **SC-005**: 4개 탭이 모두 동작한다(PLAN.md 8장 완료 기준). 각 탭의 수용 시나리오가 전부 통과한다.
- **SC-006**: 한 사용자의 저장 설계안이 다른 사용자에게 보이는 경우가 0건이다.

## Assumptions

- 002 학습된 대리모델과 003 최적화 기능이 준비된 상태다.
- 사용 환경은 캡스톤 발표·사내 네트워크 수준이며, 로그인(인증)은 범위 밖이다. 외부 공개 배포가
  필요해지면 인증을 별도 기능으로 다룬다.
- 저장 설계안은 세션 동안만 유지한다. 사용자 간 공유나 영구 저장은 범위 밖이다(PLAN.md 6.3의 "필요하면").
- 동시 사용자 규모는 5~10명이다.
- 화면 언어는 한국어, 수치 단위는 SI와 $ 기준이다.
- UI 구현 기술은 plan 단계에서 정한다(헌법 기술 제약의 기본값은 Streamlit).
